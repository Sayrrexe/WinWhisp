## [0.2.1] - 2026-05-15

### Added
- Новый метод вставки `unicode` через Win32 `SendInput` с флагом `KEYEVENTF_UNICODE` (`text.inject.type_unicode`). Промежуточные чанки во время диктовки печатаются напрямую как клавиатурные события и **не трогают буфер обмена**: до этого каждый VAD-чанк копировался в clipboard под Ctrl+V, засорял историю буфера (Win+V) и затирал то, что пользователь сам туда положил минуту назад. Теперь длинная диктовка из десятка чанков оставляет clipboard в покое — там остаётся то, что было до неё. Surrogate pairs (эмодзи, редкие CJK) обрабатываются корректно. Метод выставляется в настройках на вкладке «Вставка текста»: `unicode` по умолчанию, `paste` — старое поведение Ctrl+V на случай приложений, где SendInput Unicode не принимается (DirectInput-игры, отдельные legacy-окна).
- Настройка `injection.copy_final_to_clipboard` (по умолчанию `True`): после окончания диктовки итоговый склеенный текст кладётся в clipboard — удобно, чтобы переслать или вставить ещё раз. Можно отключить, если хочется чтобы буфер вообще не менялся ни во время, ни после диктовки.

### Changed
- `inject()` упрощён: убраны параметр `restore` и stash/restore-логика «прочитать старый clipboard → положить новый → нажать Ctrl+V → вернуть старый». Этот рестор работал заведомо ненадёжно: clipboard history Win+V всё равно запоминал промежуточный текст (то есть «восстановить как было» физически невозможно — снапшот уже в истории Windows), а сам возврат старого значения проигрывал гонку с приложениями, читающими буфер сразу после Ctrl+V (Telegram/Discord/некоторые IDE). Корректное решение лежит в плоскости «не копировать в буфер вовсе» — это и есть новый `unicode`-метод.
- Вкладка «Вставка текста» в настройках: добавлен селектор «Метод вставки» (unicode/paste) и переключатель «Копировать финальный текст в буфер». Подзаголовок и описание полей переписаны под новый смысл вкладки.
- Финальное копирование текста в clipboard в `_maybe_finish` теперь под условием `cfg.injection.copy_final_to_clipboard` (раньше копировалось всегда, без возможности отключить).

### Removed
- Поле `injection.restore_clipboard` и соответствующий toggle «Восстанавливать буфер обмена» из настроек — поведение работало некорректно (см. Changed выше) и стало бессмысленным после появления `unicode`-метода. При апгрейде старого `config.yaml` с `restore_clipboard: true` поле тихо игнорируется pydantic'ом, миграция бесплатная.

## [0.2.0] - 2026-05-15

### Added
- Вкладка "Словарь" в настройках перестала быть заглушкой: редактор `vocab.yaml` с тремя секциями — Hotwords (QListWidget с inline-добавлением и double-click для редактирования), Замены (QTableWidget "из → в" с inline-вводом, схема `dict[str,str]` из `Vocab.replacements`) и Галлюцинации (QListWidget, синтаксис с префиксом «~»); карточка Initial prompt с QPlainTextEdit для `vocab.prompt_prefix` и toggles `vocab.use_initial_prompt` / `vocab.use_hotwords`; внизу — readonly-список `BUILTIN_HALLUCINATIONS` (применяются всегда). Изменения списков/таблицы дебаунсятся 450 мс и сохраняются в `vocab.yaml` через новую `save_vocab()`; `prompt_prefix` идёт обычным путём через config.yaml. После сохранения окно эмитит сигнал `vocab_changed`, app перечитывает `vocab.yaml` и пушит новый `Vocab` в `AsrWorker.update_vocab()` — на лету, без перезапуска. Для горячей подмены prompt_prefix в `AsrWorker` добавлен `set_prompt_prefix()`, вызывается из `_apply_basic_changes` когда `vocab.prompt_prefix` приходит в `config_changed`.
- Вкладка "Внешний вид" в настройках перестала быть заглушкой: toggle `overlay.enabled`, цветовая кнопка для `overlay.accent_color` (QColorDialog, превью-свотч), цветовая кнопка с альфа-каналом для `overlay.background_rgba` (RGBA-список сохраняется атомарно через `_set_cfg_value`), слайдеры `overlay.result_hold_ms`, `overlay.bottom_margin_px`, `overlay.bars`; в "Дополнительно" — `overlay.width`, `overlay.height`, `overlay.fps`. Применение настроек требует перезапуска приложения — overlay читает `cfg.overlay.*` один раз при инициализации, runtime-апдейт через `config_changed` пока не подключён.
- Вкладка "Микрофон и запись" в настройках перестала быть заглушкой: выбор устройства ввода (список через `sounddevice.query_devices()` с пунктом "Авто" и тостом про перезапуск), параметры VAD-нарезки чанков (`chunk_min_s`, `chunk_max_s`, `chunk_silence_s`, `chunk_silence_rms`), toggle нормализации громкости; в "Дополнительно" — `keep_silence_pad_ms`, `silent_chunk_frac`, `peak_target`, `peak_max_gain`, `rms_smoothing`, `samplerate`, `channels`, `block_ms`. ASR-VAD (`asr.vad_filter`, `asr.vad_min_silence_ms`) остался на вкладке "Модель распознавания" как параметр декодера Whisper, не записи.
- Вкладка "Вставка текста" в настройках перестала быть заглушкой: в основной карточке — комбинация вставки (захват шортката через тот же диалог что и у хоткея записи, без warning'а о перезапуске — `inject()` читает комбо на каждый вызов), слайдеры пауз `pre_paste_delay_ms` (0–500 мс) и `post_paste_delay_ms` (0–1500 мс), toggle "Добавлять пробел после вставки" и combobox "Если фокус сменился"; в "Дополнительно" — toggle "Восстанавливать буфер обмена"; внизу — поясняющая подсказка про clipboard+Ctrl+V и зачем нужны задержки.

### Changed
- Поля `injection.trailing_space`, `injection.on_focus_change` и `injection.restore_clipboard` переехали из вкладки "Общие" на новую вкладку "Вставка текста" — там им место по смыслу.
- Вкладка "Общие" в настройках расширена: добавлены `injection.trailing_space` (пробел после вставки) и `injection.on_focus_change` (поведение при смене фокуса) в основную часть; в раздел "Дополнительно" добавлены `audio.max_duration_s` (слайдер 30–300 с), `injection.restore_clipboard`, `updater.enabled` и `updater.check_interval_hours` (слайдер 1–48 ч).
- Вкладка "Модель распознавания" в настройках расширена: в основную часть добавлены `asr.task` (combo transcribe/translate) и `asr.condition_on_previous_text` (toggle); добавлен раздел "Декодирование" с `asr.sampling_strategy`, `asr.best_of`, `asr.temperature`, `asr.no_speech_threshold`, `asr.repetition_penalty`; добавлен раздел "Эвристики качества" с `asr.compression_ratio_threshold`, `asr.log_prob_threshold`, `asr.word_timestamps`.

## [0.1.13] - 2026-05-15
### Added
- Single-instance lock на старте через named Windows-мьютекс. Если WinWhisp уже запущен, второй процесс молча выходит с сообщением в stderr. Раньше второй (и третий, и седьмой — в логах фиксировались такие случаи) инстанс тихо стартовал, оба подписывались на один и тот же глобальный хоткей через `keyboard`-lib, и каждая диктовка дублировалась: оба процесса параллельно гнали Whisper и оба инжектили текст в окно. Lock auto-release при смерти процесса, никаких лок-файлов чистить вручную не надо.

### Changed
- PROCESSING-watchdog переписан с фиксированного «жди `max_duration_s + 30s`» на inactivity-таймер: рестартуется на каждый пришедший `_on_transcription_ready` (включая пустые/дропнутые). Таймаут — 30 секунд бездействия. Раньше при дефолтном `max_duration_s=120` пользователь ждал 2.5 минуты, прежде чем зависший PROCESSING сбрасывался; теперь — 30 секунд после последнего сигнала от ASR.
- При срабатывании watchdog'а теперь дополнительно вызывается `asr.request_reload()`. Сценарий: если `faster-whisper.transcribe()` завис в C-коде (а не сигнал потерялся), сброс state в IDLE без перезагрузки движка не помогал — следующий чанк всё равно вставал в очередь за зависшим. Reload убивает модель в треде ASR и перезагружает её.
- Добавлены диагностические `INFO`-логи в `_on_audio_chunk` (`chunk in: state=X pending->N dur=Ys`) и `_on_transcription_ready` (`ready: state=X pending->N text_len=K`). Зависание PROCESSING при `pending=0 emit_tail=True` (tail-чанк ушёл, но воркер за 13+ секунд не выдал `ready`) — без этих логов невозможно отличить три гипотезы: tail-чанк не доехал до `_on_audio_chunk` (потерян Qt-signal), `transcribe()` висит в C-коде faster-whisper, или ready пришёл, но `_maybe_finish` не сработал. Теперь сетка точек видна в логе и при следующем зависе можно поставить диагноз.

### Fixed
- Состояние PROCESSING больше не залипает после короткой/тихой диктовки. Сценарий: пользователь зажимает хоткей, успевают эмитнуться все VAD-чанки до отпускания (или пресс короткий и микрофон поднял в основном тишину), на отпускании `audio.stop(emit_tail=True)` обрезает тихий хвост и ничего не отправляет в worker, а `_pending_chunks == 0`. Раньше `_finalize_release` всё равно ставил `State.PROCESSING`, ждать новых `ready`-сигналов было неоткуда — оверлей «обрабатываю» висел до перезапуска. Теперь `AudioCapture.stop()` возвращает `tail_emitted: bool`, и финализация уходит обратно в IDLE если ни один чанк не в работе и хвост дропнут как тишина.
- Single-instance lock больше не отключается молча в установленной сборке. `_acquire_singleton_or_exit` переписан с `pywin32` (`win32event.CreateMutexW` + `win32api.GetLastError`) на чистый `ctypes.windll.kernel32`. В PyInstaller-бандле `win32event.pyd` и `winerror.py` не подтягивались (`hiddenimports` содержал только `win32clipboard/gui/api/con`), `ImportError` на `win32event` тихо возвращал управление и singleton-проверка пропускалась целиком. На практике это давало два-три параллельно работающих инстанса winwhisp.exe (оба подписаны на `right ctrl` через `keyboard`-lib, оба гнали Whisper и оба инжектили текст), что и проявлялось как «дублирование» и странные обрезы вставки на стыках pyperclip-stash/restore. `ctypes`-путь не зависит от того, что собрал PyInstaller; `win32event` и `winerror` всё равно добавлены в `hiddenimports` как belt-and-braces.
- Короткое тихое слово на самом конце диктовки («всё», «ага», «ок») больше не съедается trim'ом перед отправкой в Whisper. `_trim_tail_silence` использовал то же 0.8с-окно, что и silence-cut во время записи, и для короткого (200–400мс) негромкого (RMS 0.02–0.03) слова с типичным 1с release-tail-хвостом средняя энергия в 0.8с-окне размазывалась ниже порога — функция возвращала `None`, и tail-чанк не доезжал до ASR (никакого лога «dropped» — `_trim_tail_silence` обрезает молча). Теперь для tail-trim применяется отдельное 200мс окно (`_tail_silence_samples = min(silence_samples, 200ms)`), которое улавливает короткие речевые всплески даже на фоне длинного силенса. Окно для in-recording silence-cut (`_silence_samples`) не меняется — там 0.8с по-прежнему правильное значение, чтобы случайные межсловные паузы 200–400мс не дробили реплику на куски.

## [0.1.12] - 2026-05-12
### Changed
- Авто-обновление больше не выглядит для Windows Defender как dropper. Скрипт-обёртка над инсталлятором (`%LOCALAPPDATA%\WinWhisp\updates\...`) переименован с `run_update.cmd` в `WinWhisp-update.cmd`, запускается без флага `CREATE_NO_WINDOW` (короткое cmd-окно теперь видно, как и у обычных апдейтеров) и больше не удаляет сам себя после установки. Сочетание «скрытое окно + скачивание .exe + silent install + самоудаление .cmd» — поведенческая сигнатура, на которую тренирована эвристика `Trojan:Win32/Bearfoos.A!ml`; именно она сработала на 0.1.10–0.1.11, когда `.cmd`-обёртка появилась. Скрипт остаётся на диске и будет перезаписан при следующем обновлении.

## [0.1.11] - 2026-05-12
### Changed
- Live-сессия теперь передаёт прокатывающийся контекст в Whisper как `initial_prompt`: последние 3 успешно расшифрованных чанка текущей сессии добавляются к vocab-промпту (с обрезкой по словам до ~450 символов). Раньше каждый чанк уходил в `engine.transcribe` только со статическим vocab-промптом — Whisper не знал, что только что произнесли, и ошибался в словоформах и на стыках слов. Контекст сбрасывается на каждое нажатие хоткея, файловый пайплайн не затронут.
- Postprocess получил `streaming` режим — на live-пути теперь срезаются ведущие/трейлинг `…` и `...`, а также висячие тире/дефисы в конце реплики. Файловые транскрипции (с таймкодами) идут прежним путём без среза, чтобы не ломать SRT-сегменты.

### Fixed
- Whisper-петли в тишине и шумных хвостах больше не пролезают в текст. Новый детектор `is_repetition_loop` отсекает результаты, где одна и та же 1–4-словная фраза повторяется подряд 4+ раза (например, «Vmware vmware vmware vmware vmware» или «iPhone X, iPhone X, iPhone X, …»). Срабатывает и в PTT-диктовке, и в файловых джобах (с фильтрацией на уровне отдельных SRT-сегментов).
- Расширен встроенный blocklist галлюцинаций: добавлены `~продолжение в следующей`, `~продолжение в следующем` и `~pydancrypt` — в логах за 2 недели такие галлюцинации Whisper встречались и попадали в инжект (особенно «Pydancrypt» как короткое наваждение в тишине, искажение хотворда `pydantic`).
- Главная причина Whisper-«хвостов» («Спасибо за просмотр», «продолжение в следующем» и т. п.) в live-диктовке — устранена в источнике, а не блок-листом. Раньше каждый чанк, отрезанный по тишине, заканчивался ~0.8 с пустого хвоста (`chunk_silence_s` целиком включался в эмит), и для Whisper это был учебниковый триггер для outro-токенов. Теперь silence-cut эмитит speech + короткий акустический pad (`audio.keep_silence_pad_ms`, по умолчанию 120 мс), а саму тишину дропает из carry-over, чтобы следующий чанк не стартовал с молчания.
- Хвостовой чанк, который улетает в ASR при отпускании горячей клавиши, теперь обрезается по тишине: если пользователь отпустил кнопку в паузу — короткое почти-молчание не доходит до Whisper и не порождает outro. Полный silence-tail дропается, короткое слово на release эмитится как есть.
- ASR-воркер на live-пути теперь сначала проверяет, не молчание ли пришло (`is_mostly_silent`), и в этом случае не дёргает Whisper вовсе. Громкость поднимается через peak-normalize (`audio.peak_normalize`, до +18 дБ с клипом по 0.95) — Whisper лучше работает с речью на нормальной громкости, как и в файловом пайплайне (там это делает ffmpeg `loudnorm`).
- Для коротких чанков (< `asr.short_audio_s`, по умолчанию 1.5 с) отключён `temperature_fallback` и поднят `no_speech_threshold` (`asr.short_audio_no_speech_threshold`, по умолчанию 0.75 против базовых 0.6). Именно высокие температуры на коротком молчании порождают уверенный outro; раньше для них модель оставалась без `initial_prompt`, без condition_on_previous_text и с полным fallback-ladder до t=1.0.

## [0.1.10] - 2026-05-11
### Added
- Транскрипция файлов теперь выдаёт SRT с настоящими таймкодами от Whisper по каждой фразе, а не одной строкой на 30-секундный чанк (`files.srt_use_segments`, по умолчанию включено). Старый режим «одна реплика на чанк» остаётся доступным через настройку.
- Тонкие настройки качества faster-whisper в `asr`: `temperature_fallback`, `no_speech_threshold`, `log_prob_threshold`, `compression_ratio_threshold`, `repetition_penalty`, `word_timestamps`, `task` (`transcribe`/`translate`), `sampling_strategy` (`beam`/`greedy`), `best_of`. Дефолты подобраны под рабочие пресеты Whisper и не меняют поведение PTT-диктовки.
- Нормализация громкости звуковой дорожки при извлечении (ffmpeg `loudnorm`, `files.loudnorm`, по умолчанию включена) — тихие записи и записи с большим LRA транскрибируются стабильнее.

### Fixed
- Авто-обновление теперь действительно перезапускает приложение после установки новой версии. Раньше расчёт был на Inno Setup флаги `/CLOSEAPPLICATIONS /RESTARTAPPLICATIONS` и `RestartApplications=yes`, но они работают только если приложение зарегистрировано в Windows Restart Manager — для tray-app это не так, поэтому WinWhisp оставался выключенным после обновления. Теперь установщик оборачивается во временный `.cmd`-скрипт (`%LOCALAPPDATA%\WinWhisp\updates\run_update.cmd`), который ждёт завершения silent-инсталлятора и сам запускает обновлённый `winwhisp.exe`; само приложение завершает процесс через 1.5 сек после старта установщика, чтобы освободить файлы для замены.

## [0.1.8] - 2026-05-02

## [0.1.4] - 2026-04-27
### Added
- New "Files" section in the settings window: drag audio or video into the window (or open it via tray → "Files…") and the audio track is extracted with ffmpeg and saved as `.txt` and `.srt` in `Documents\WinWhisp\transcripts\`. Supports mp3, mp4, wav, m4a, mkv, ogg, opus, and other common formats.
- Hotkey transcription takes priority over file transcription: pressing the hotkey pauses file processing at the current segment, and recognition resumes automatically once the hotkey is released.
- New "Files…" tray menu item with an active-jobs counter opens the window directly on the "Files" page.
- New `files` section in `config.yaml` to configure chunk length, silence threshold, output directory, and output formats.

### Changed
- ffmpeg is now bundled with the installer build, so file transcription works out of the box without requiring ffmpeg in PATH.
